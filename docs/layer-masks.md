# Windows 레이어 마스크 구현 및 검증

2026-09-23. 기준 `74ab8fe` 이후 로컬 구현. macOS 원본 코드는 수정하지 않는다.

## 사용법

1. 레이어를 선택하고 **LAYER MASK → + Reveal**(전체 표시) 또는 **+ Hide**(전체 숨김)를 누른다.
2. **Edit mask**에서 브러시를 선택한다. **Mask gray %** 0은 숨김, 100은 표시, 중간 값은 부분 표시다. 브러시 크기·경도·불투명도를 함께 사용할 수 있다.
3. 마스크 지우개는 검정으로 칠해 숨긴다. 다시 드러내려면 브러시와 gray 100을 사용한다. **Edit image**를 선택하면 원본 픽셀 편집으로 돌아간다.
4. **Mask enabled**를 끄면 원본이 보이고, **Remove**는 마스크만 제거한다. 추가·편집·삭제·활성화 변경은 Undo/Redo로 되돌린다.
5. Move 및 레이어 크기·회전·뒤집기는 마스크와 함께 적용된다. 변환 수치는 **Position, size and rotation**을 펼쳐 조절한다.

마스크 편집은 원본 이미지 타일을 변경하지 않는다. Esc·캡처 상실·비활성화 시 편집 취소를 유지한다. 비활성 마스크는 다시 켠 뒤 칠하도록 안내한다. 편집 대상은 세션과 Undo에 반영하지만 프로젝트 파일에는 저장하지 않으며, 프로젝트를 열면 원본 이미지 편집 대상으로 시작한다.

## 저장 및 지원 범위

- `.comp` 버전 4–8의 기본 연결 마스크를 읽고 버전 8로 저장한다. 기존 마스크 없는 버전 1–8 문서는 계속 지원한다.
- 마스크 파일은 `images/<UUID>.mask.png`, 8비트 회색조 PNG, 알파 없음이다. 흰색은 표시, 검정은 숨김이며 색 공간 변환 없이 커버리지 값을 유지한다.
- `maskEnabled`가 없거나 null이면 true, `maskLinked`가 없거나 null이면 연결된 것으로 읽는다. 파일 없는 마스크 메타데이터는 거부한다.
- 원본 이미지와 같은 픽셀 크기 또는 1×1 균일 마스크를 지원한다. 1×1은 실제 변화가 있는 첫 스트로크에서 원본 격자로 확장한다. 동일한 초기 타일은 공유한다.
- 내부 표현은 불변 RGBA 회색조 타일이다. 파일은 1바이트 회색조지만 수정된 내부 픽셀은 4바이트가 필요하다. 마스크 타일도 기존 Undo 메모리 한도에 포함한다.
- 원본 소스 합계 100MP와 별도 마스크 합계 100MP를 검사한다. 투명한 빈 레이어라도 마스크가 있으면 원본 격자 보존을 위해 투명 원본 PNG를 저장한다.
- 분리 이동(`maskLinked: false`), 독립 배치(`maskPlacement`), 다른 레이어 참조(`maskSourceID`), 다른 해상도의 마스크 및 그룹 마스크는 명확히 거부한다. 미지원 기능을 조용히 버리지 않는다.
- 마스크를 삭제하고 저장하면 오래된 마스크 자산이 새 패키지에 남지 않는다. 게시 실패 시 이전 마스크와 원본 파일을 복구한다.

Mac의 소스 규격에 맞춘 구현이며 실제 Mac 앱에서 생성한 대표 문서의 양방향 열기는 아직 미검증이다. Windows는 소스 픽셀에 마스크를 곱한 뒤 변환·샘플링하므로 Mac의 별도 마스크 클립 및 고품질 필터와 변환된 경계의 픽셀 결과가 완전히 같음을 주장하지 않는다.

## 검증

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1 -Test
dotnet run --project Compositor.Benchmarks/Compositor.Benchmarks.csproj -c Release -- --masks artifacts/mask-benchmark.json
powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1 -Publish
```

Release 빌드 경고 0개·오류 0개, xUnit **75개 통과**. 검증 항목:

- 검정/회색/흰색 커버리지와 premultiplied RGBA, 비활성 복원.
- 타일 경계와 교차 스트로크, 흰색 복원·지우개 숨김, 원본/과거 마스크 불변성.
- 마스크 편집·삭제·취소 후 Undo/Redo와 편집 대상·저장 상태·히스토리 타일 집계.
- 100%/150%/200% 상당 뷰포트에서 증분/전체 합성 일치, 이동·회전·뒤집기·활성화·삭제·Undo. 변경되지 않은 회전 오버레이도 포함한다.
- 회전된 레이어의 부분 클립에서 재현된 150% 배율 픽셀 오차를 수정했다. 임의 각도(90도 배수 제외)로 회전된 표시 레이어가 있는 문서는 픽셀이 바뀌면 전체 뷰포트를 다시 합성한다. 비회전 편집은 타일 손상 영역을 사용한다.
- 회색조 PNG 헤더 및 마스크 픽셀 왕복, 비활성 마스크 보존, PNG 출력 일치, 숨김 마스크 JPEG의 흰 배경.
- 저장 게시 실패의 원본 보존, 오래된 마스크 자산 제거, 잘못된 경로·누락·컬러 마스크·버전·크기·미지원 배치 거부.
- 숨김 WPF에서 실제 핸들러를 통해 추가/대상 선택/흑백 브러시/지우개/활성화/삭제/Undo/Redo/취소/저장/재열기/PNG 출력 검증. 결과는 `artifacts/ui-smoke.masks.json`, 화면은 `artifacts/ui-smoke.png`.

self-contained win-x64 배포 폴더의 `Compositor.Windows.exe`로도 기존 안정화 검증과 마스크 검증을 모두 통과했다. 배포 검증 결과는 `artifacts/published-mask-smoke.checks.json`, `artifacts/published-mask-smoke.masks.json`, `artifacts/published-mask-smoke.png`에 남긴다.

물리 마우스·펜·여러 모니터 DPI 전환 및 실제 저장 중 강제 종료는 기존 미검증 항목으로 남는다.

## 성능

2026-09-23 00:20 UTC, Intel Core 5 210H, RAM 약 64GiB, Release CPU 경로. 각각 독립적인 4000×4000 소스 1/3/6개, 최하단 마스크에 800px soft 검정 브러시, 120회 입력 × 2스트로크, 1000×1000 Skia 합성이다. 위 레이어는 60% 불투명도와 Normal/Multiply를 섞었다. 회전 없음. 실제 WPF 표시·장치 입력 지연은 포함하지 않는다.

| 레이어 | 최초 합성 | 갱신 p95 최대 | 스트로크 종료 최대 | working set 범위 |
|---|---:|---:|---:|---:|
| 1 / 16MP | 94.2ms | 22.4ms | 5.2ms | 425–465MiB |
| 3 / 48MP | 132.9ms | 20.8ms | 2.4ms | 912MiB |
| 6 / 96MP | 233.9ms | 23.0ms | 2.3ms | 1296–1297MiB |

픽셀마다 타일을 찾던 초기 구현은 p95 43–47ms로 기준을 넘었다. 행 구간마다 타일을 조회하고 전체 표시 값의 곱셈을 생략한 뒤 위 결과를 얻었다. 모든 측정은 초기 p95 ≤33.3ms·종료 ≤100ms 기준을 통과했다. 최초 합성 및 1×1 마스크가 확장되는 첫 입력은 p95만으로 설명되지 않는 비용이며, 장치 입력부터 화면 갱신까지의 보장을 뜻하지 않는다. 회전 문서의 전체 합성 성능은 별도 측정이 필요하다.

## 다음 작업

이 기록 이후 레이어 그룹을 구현했다. 현재 결과는 [그룹 검증](layer-groups.md)을 참고한다. 당시 계획은 다음과 같다: 레이어 그룹. 부모/자식 모델·그룹 저장 호환 → 패널 계층/이동 → 그룹 표시·불투명도·pass-through 합성 → Undo/Redo와 픽셀 회귀 순서로 진행한다. 그룹 마스크와 독립 배치 마스크는 별도 호환 범위로 검증해야 한다.
