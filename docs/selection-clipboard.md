# Windows 선택 클립보드

2026-10-06: 선택 복사/합성 복사/잘라내기/붙여넣기를 Edit 메뉴와 단축키에 연결했다.

## 사용 및 원본 대조

macOS/Compositor/Document/SelectionClipboard.swift를 기준으로 했다.

- Ctrl+C: 활성 이미지의 원본 픽셀을 문서 좌표로 복사한다. 레이어 불투명도·합성 모드·효과·마스크는 적용하지 않는다. 마스크 편집 중에는 마스크 농도를 회색 이미지로 복사한다.
- Ctrl+Shift+C: 보이는 전체 레이어의 불투명도·합성·마스크·효과가 반영된 결과를 복사한다.
- 선택이 없으면 캔버스 크기, 선택이 있으면 페더를 포함하는 정수 픽셀 경계와 선택 농도를 적용한다. 빈 선택은 복사하지 않는다.
- Ctrl+X: 선택을 복사한 뒤 원본 픽셀을 지운다. 마스크에서는 선택 농도를 검게 만든다. 클립보드 기록 실패 시 픽셀 삭제와 Undo 추가가 모두 일어나지 않는다.
- Ctrl+V: 활성 레이어 위/그룹 안에 새 레이어로 붙여넣고 선택을 해제한다. 앱에서 복사한 클립보드가 그대로 유지되면 원래 위치, 외부 이미지면 캔버스 중앙에 놓는다.
- 텍스트 입력란에 포커스가 있으면 기존 텍스트 복사·붙여넣기 단축키를 방해하지 않는다.
- 붙여넣기는 문서의 레이어/픽셀 예산을 검증하고 활성 레이어 변경까지 한 Undo로 관리한다.

## Windows 전송

WindowsPixelClipboard는 PNG와 WPF BitmapSource를 함께 게시한다. 읽기는 PNG 우선, BitmapSource 대체 경로다. PNG는 Skia 작업 색 공간(sRGB)으로 디코딩한다. 비트맵에 색 프로필이 있으면 WPF 색 변환 후 premultiplied BGRA를 작업 RGBA로 변환한다.

클립보드 변경 시퀀스와 임의 소유권 표식을 함께 확인한다. 둘 중 하나라도 달라지면 캐시된 픽셀/위치를 재사용하지 않는다. 유효하지 않은 PNG, 크기 제한 초과, 점유된 클립보드는 오류를 알리고 문서 편집을 하지 않는다.

최대 100MP, 변당 30,000px, 인코딩 512MiB 제한을 적용한다. PNG를 지원하지 않는 외부 프로그램은 비트맵 대체 형식의 알파 처리에 따라 결과가 달라질 수 있으므로 실제 상호 운용 검증이 필요하다.

## 검증 범위

- 코어 411개 테스트: 원본/합성/마스크 복사, 불투명도, 페더 알파, 캔버스 범위, 빈 선택, 실패한 잘라내기의 원본/이력 보존, 붙여넣기 위치/그룹/선택 해제/활성 레이어/Undo, 균일 마스크 잘라내기.
- 실제 WPF 스모크: PNG/BitmapSource IDataObject 생성 및 디코딩, 알파·색상 왕복, 소유권/시퀀스 변경, 일반 메뉴 핸들러, 실패 복구, 손상 PNG와 빈 클립보드.
- 자동 스모크는 주입한 IDataObject 저장소를 사용한다. 사용자의 시스템 클립보드를 읽거나 덮어쓰지 않는다. 따라서 실제 OLE 클립보드 게시와 다른 프로그램과의 왕복은 아직 검증 완료로 표시하지 않는다.
- 큰 이미지 복사/붙여넣기 시간·메모리와 외부 프로그램별 PNG/비트맵 알파 호환성은 잔여다.
- Layer via Copy(Ctrl+J), 전체 레이어 복제, 파일/텍스트/벡터 클립보드 가져오기는 이 단계에 포함하지 않는다. 원본에서 지원하는 레이어 복제는 후속 작업이다.

최종 Release 빌드 경고/오류 0, 411개 테스트 및 WPF 스모크 통과. artifacts/publish-clipboard/Compositor.Windows.exe 패키지의 verify-portable.ps1 -Runs 1 격리 실행도 통과했다. 이 검증 역시 주입한 클립보드 전송 계층을 사용하므로 실제 프로그램 간 왕복을 대신하지 않는다.
