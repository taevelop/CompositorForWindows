# 선택 픽셀 변형 기반

원본 Document/FloatingSelection.swift의 beginSelectionTransform, floatingSelectionTransform, FloatingMerge를 대조했다.

## 구현

SelectionTransformPixels는 문서 좌표에서 선택한 이미지 픽셀과 원본을 준비하고, 이동·회전·크기·뒤집기 설정으로 결과 문서를 계산한다. 각 결과는 원본 선택 픽셀에서 다시 계산하여 반복 미리보기의 재샘플링 손실을 누적하지 않는다.

변형된 픽셀은 원래 레이어의 역변환으로 소스 격자에 합성한다. 바깥 영역은 원본처럼 문서 경계 상자 → 소스 경계 상자로 환산하여 레이어를 확장한다. 마스크의 기존 영역은 유지하고 새 여백은 흰색으로 채운다. 회전·뒤집기·그룹 부모·불투명도·효과 설정은 보존한다. 선택 윤곽은 같은 변환을 적용하며 페더 수치는 유지한다.

초기 변형과 정확히 같은 설정은 원본 Document 참조를 그대로 반환한다. 부드러운 선택 경계의 절단/재합성으로 생기는 무변경 이음을 방지한다. 현재 마스크 대상·그룹·조정·숨긴 레이어는 선택 픽셀 변형에서 제외한다.

출력 레이어/문서 이미지·마스크 예산을 할당 전에 검사하고 결과의 Undo 보존 한도도 검사한다. 원본은 불변이며 취소/오류 시 세션에 결과를 적용하지 않는다.

## 검증

코어 474개 테스트에 원점 복원·미리보기 누적 방지·이동/뒤집기/확대/회전·선택 윤곽·premultiplied alpha·흰 마스크 확장·잘못된 대상/크기/취소 검사를 포함했다. 회전/뒤집기가 있는 원본 레이어로의 재합성, 그룹/효과 보존, 한 번의 Undo/Redo와 프로젝트 저장 왕복도 확인한다.

## 연결 잔여

아직 Ctrl+T와 변형 핸들/회전/비율/뒤집기 UI에 연결하지 않았다. 명령 상태·미리보기·확정/취소·도구/레이어 전환과 실제 WPF 검증을 이어간다. 원근/왜곡, 독립 마스크 변형 및 다중 레이어 변형은 별도 후속 범위다.

현재 준비 단계는 기존 CPU 복사 렌더를 사용하며 결과 합성은 전체 레이어 비트맵을 만든다. 대용량 지연·피크 메모리와 취소 응답성 개선은 잔여다. Skia 샘플링과 실제 Mac 결과의 픽셀 단위 동등성은 검증하지 않았다. 원본 일부 합성 코드의 효과 누락은 재현하지 않고 Windows는 효과를 보존한다.

실행 패키지는 artifacts/publish-selection-scroll/Compositor.Windows.exe를 유지한다. 이번 연산 기반만으로 새 UI 기능을 배포하지 않는다.

./build.ps1 -Test: 경고/오류 0, 코어 474개 및 기존 실제 WPF 회귀 검사 통과.

## 핸들 연산과 편집 상태

TransformDrag는 원본 LayerTransform.swift의 이동/회전/8개 크기 핸들 규칙을 구현한다. 회전한 좌표에서 반대편 기준점을 고정하고 Alt 중심 조절, Shift 축 제한/15도 회전, 비율 잠금의 Shift 임시 반전, 반대쪽 경계를 넘을 때 뒤집기를 처리한다. 핸들 위치는 이미지 뒤집기와 무관한 기하 좌표를 사용한다. 포인터가 움직이지 않으면 원본 변형 참조를 그대로 반환한다.

LayerTransformEdit는 전체 이미지 레이어 또는 선택 픽셀의 미리보기·확정·취소를 한 트랜잭션으로 관리한다. 잘못된 미리보기는 취소하고 원본을 복원한다. 선택이 캔버스 밖에 있어 추출할 수 없을 때 전체 레이어 변형으로 넘어가지 않고 명시적으로 거부한다. 연결 마스크 대상에서는 기존 레이어와 마스크가 함께 변형된다.

이 단계의 컨트롤러는 단일 이미지 레이어/선택 픽셀만 지원한다. 그룹·다중 레이어·독립 마스크·왜곡은 여전히 후속 범위다. Ctrl+T, 시각적 핸들/회전/수치·슬라이더 UI와 도구 전환 규칙 연결은 아직 남아 있다. 기존 실행 패키지를 유지한다.

핸들/편집 상태 검증: ./build.ps1 -Test 경고/오류 0, 코어 488개와 기존 실제 WPF 회귀 검사 통과. 회전 핸들 8개·반대편/중심 기준점·뒤집기·비율·이동축·회전 스냅·무변경/취소/오류/Undo를 검사했다.
