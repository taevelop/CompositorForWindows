# 스포이트 구현 현황

2026-10-07: 합성 색상 샘플링 연산을 구현했다. 아직 I 도구/Alt 임시 스포이트/색상 선택창에는 연결하지 않았다.

원본 Document/ColorPalette.swift의 sampleCompositeColor는 화면의 체크무늬나 선택 윤곽을 제외한 보이는 레이어 합성 결과를 sRGB 단일 픽셀로 읽는다. 문서 좌표는 내림 처리하고 캔버스 밖 및 알파 0은 샘플 없음으로 처리한다. premultiplied 채널을 알파로 나누고 8비트 RGB로 반올림한다. 현재 레이어/평균 범위 선택은 이 원본 경로에 없다.

CompositeColorSampler는 화면/출력과 같은 CanvasRenderer와 1×1 출력 비트맵을 재사용한다. IDisposable로 비트맵/캔버스/렌더러 캐시를 정리한다. 조정과 효과의 내부 합성이 전체 문서 버퍼를 사용할 수 있으므로 1×1 출력이 전체 연산량이나 메모리까지 작다는 의미는 아니다. UI 연결 후 큰 문서 연속 샘플링의 지연과 메모리를 측정해야 한다.

검증: 코어 541개 및 기존 WPF 회귀 검사 통과. 소수 좌표 내림, 반투명 RGB 복원, 투명/범위 밖/NaN/무한대, 그룹 불투명도+마스크+숨긴 레이어의 전체 합성 픽셀 일치, 조정 문서 변경/원래 문서 복귀 시 캐시, 중복 Dispose 및 해제 후 호출 거부를 검사했다. 실제 Mac 색상 동등성은 보류다.

남은 연결: I 도구와 브러시 Alt 임시 샘플링, 클릭/드래그/해제/취소/캡처 상실, 색상 비교 링, 열린 색상 선택창 샘플링. 원본 Rendering/EditorCanvas.swift의 sampleColor는 팔레트 전경색을 갱신하며, 색상 선택창이 열렸다면 해당 선택창의 미리보기 색상만 갱신한다. 문서 픽셀/Undo는 변경하지 않아야 한다.
