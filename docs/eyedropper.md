# 스포이트 구현 현황

2026-10-07: 합성 색상 샘플러와 I 도구/브러시·지우개 Alt 임시 스포이트를 연결했다. 색상 비교 링과 열린 색상 선택창 샘플링은 아직 남아 있다.

원본 Document/ColorPalette.swift의 sampleCompositeColor는 화면의 체크무늬나 선택 윤곽을 제외한 보이는 레이어 합성 결과를 sRGB 단일 픽셀로 읽는다. 문서 좌표는 내림 처리하고 캔버스 밖 및 알파 0은 샘플 없음으로 처리한다. premultiplied 채널을 알파로 나누고 8비트 RGB로 반올림한다. 현재 레이어/평균 범위 선택은 이 원본 경로에 없다.

CompositeColorSampler는 화면/출력과 같은 CanvasRenderer와 1×1 출력 비트맵을 재사용한다. IDisposable로 비트맵/캔버스/렌더러 캐시를 정리한다. 조정과 효과의 내부 합성이 전체 문서 버퍼를 사용할 수 있으므로 1×1 출력이 전체 연산량이나 메모리까지 작다는 의미는 아니다. UI 연결 후 큰 문서 연속 샘플링의 지연과 메모리를 측정해야 한다.

검증: 코어 541개 및 기존 WPF 회귀 검사 통과. 소수 좌표 내림, 반투명 RGB 복원, 투명/범위 밖/NaN/무한대, 그룹 불투명도+마스크+숨긴 레이어의 전체 합성 픽셀 일치, 조정 문서 변경/원래 문서 복귀 시 캐시, 중복 Dispose 및 해제 후 호출 거부를 검사했다. 실제 Mac 색상 동등성은 보류다.

남은 연결: 색상 비교 링, 열린 색상 선택창 샘플링, 대형 문서 샘플링 지연/메모리 측정. 원본 Rendering/EditorCanvas.swift의 sampleColor는 팔레트 전경색을 갱신하며, 색상 선택창이 열렸다면 해당 선택창의 미리보기 색상만 갱신한다. 문서 픽셀/Undo는 변경하지 않아야 한다.

## 도구와 입력 연결

I 도구 또는 브러시/지우개에서 Alt+왼쪽 버튼으로 합성 색상을 전경색에 반영한다. 원본은 지우개가 브러시의 모드이므로 Windows의 별도 Eraser 도구도 Alt 샘플링을 지원한다. 누른 상태로 이동하면 연속 샘플링하며 다른 버튼이 입력을 가로채지 않는다. 선택 마스크와 무관하게 화면의 합성을 읽고, 마스크 편집 중에도 원본처럼 실제 전경색을 갱신하되 마스크 회색 농도는 바꾸지 않는다.

해제·Esc·캡처 상실·도구 전환은 입력 상태를 정리하며 마지막으로 읽은 색상을 유지한다. 문서 픽셀, 수정 상태, Undo는 바꾸지 않는다. 화면 좌표는 현재 확대/이동을 적용해 문서 좌표로 변환한다. I 및 Alt 입력은 기존 Ctrl+I 가져오기와 텍스트 입력 단축키를 유지한다. 커서는 현재 십자이며 원본 비교 링/전용 커서 완성은 후속 품질 범위다.

WPF 검사: 클릭/드래그, 투명/밖 영역의 이전 색상 보존, 버튼 조합, Alt 브러시/지우개, 취소/도구 전환, 확대/이동 좌표, 문서 스냅샷/Undo 불변성. Esc와 캡처 상실은 합성 WPF 이벤트로 검사한다. 실제 마우스·키보드 실기와 Mac 결과 비교는 대체하지 않는다.

최종 검증: 코어 541개, 확장 WPF 검사 및 I 도구 화면 정렬 확인 통과. artifacts/publish-eyedropper/Compositor.Windows.exe 생성 및 verify-portable.ps1 -Runs 1 통과. 별도 Windows/Mac 검증 보류 유지.

## 색상 비교 링

2026-10-07: 원본 SampleRingOverlay의 116 DIP 영역, 반지름 43 DIP, 회색 24 DIP 외곽선과 16 DIP 색상 선을 연결했다. 위쪽은 현재 샘플이고 아래쪽은 드래그 시작 전 전경색이다. 확대 배율과 분리된 화면 좌표로 그리며 샘플링 합성에는 포함하지 않는다. Sample ring 체크박스와 탭별 설정 복원을 지원하고 해제/취소 시 제거한다.

검증: 코어 541개와 WPF 회귀 통과. 두 반원 색상, 외곽선, 투명 중심, 표시 끄기, 설정 복원, 취소 후 제거를 검사하고 생성 이미지를 확인했다. 실제 다중 DPI 마우스 실기와 Mac 색상 비교는 미검증이다. 열린 색상 선택창 샘플링과 대형 문서 성능 측정은 계속 남아 있다.
`artifacts/publish-sample-ring/Compositor.Windows.exe` 생성 및 verify-portable.ps1 -Runs 1 통과. 개발 PC 격리 실행 결과이며 별도 Windows PC 실기를 대체하지 않는다.

## 색상 선택창 샘플링 1차

2026-10-07: 전경/배경 및 중첩 효과 색상 선택창에 Sample canvas 버튼을 연결했다. 기존 모달 창의 소유자 체인에서 실제 편집 캔버스를 찾고, 캔버스 위치에 투명 입력 창을 띄워 동일 합성 샘플러로 읽는다. 문서와 효과 미리보기는 입력 차단 상태를 유지한다. 클릭/드래그 후 해제하면 선택창의 색상만 바뀌고 Use color로 확정한다. Esc/캡처 상실은 샘플링을 취소한다. 투명 픽셀은 직전 유효 색상을 유지한다.

코어 541개와 WPF 회귀 통과. 실제 중첩 ShowDialog 흐름에서 확대/이동 좌표, 투명 픽셀, 샘플 확정/취소, 전경색·문서·Undo 불변성을 검사했다. 물리 입력은 합성 호출로 대체 검증하지 않았다. 원본의 열린 선택창 연속 미리보기 및 비교 링은 이 경로에 아직 연결하지 않았으며, 다중 DPI/모니터 위치 및 실제 마우스 검증과 함께 후속 범위다. 이 단계로 색상 선택창 샘플링 전체가 완료된 것으로 처리하지 않는다.
배포: artifacts/publish-picker-sampling 생성 및 격리 WPF 실행 1/1 통과. 선택창 화면에서 버튼·색상표·RGB/HEX 입력 정렬을 확인했다. 별도 PC 검증 보류는 유지한다.

## 선택창 연속 미리보기와 비교 링

2026-10-07: 모달 샘플링 창의 유효 샘플을 선택창에 즉시 반영하고, 샘플링 취소/실패 시 시작 색상으로 복원한다. 선택창의 Use color 전에는 팔레트/효과 설정을 확정하지 않는다. 입력 창의 WPF 비교 링은 위쪽 현재 색상/아래쪽 시작 색상, 회색 외곽선 및 화면 반지름 43 DIP를 유지하고 문서의 Sample ring 표시 옵션을 따른다. 투명 위치에서도 마지막 유효 샘플을 표시한다.

검사에는 선택창의 종료 전 실시간 색상, 취소 후 복원, 문서/팔레트 불변성, WPF RenderTargetBitmap의 두 반원 픽셀과 표시 끄기를 포함한다. 물리 마우스/캡처 상실/다중 DPI·모니터 배치 및 대형 문서 성능은 계속 잔여다. 원본과 달리 Windows에서는 Sample canvas 버튼으로 모달 샘플링을 시작한다.
검증 결과: 경고/오류 0, 코어 541개 및 확장 WPF 검사 통과. artifacts/publish-picker-preview 패키지 격리 실행 1/1 통과. 실제 Mac/별도 PC 검증 보류 유지.

## 4K 성능 측정 (2026-10-07)

재현: `dotnet run --project Compositor.Benchmarks -c Release -- --eyedropper artifacts/eyedropper-benchmark.json`. 별도 프로세스로 2회 측정했다. 4000×4000 반투명 이미지, 이동 샘플 20회, 불투명도 변경 및 원본 스냅샷 복귀를 검사한다. WPF 입력/화면 표시 지연은 포함하지 않는다.

| 문서 | 최초 샘플 2회 범위 | 연속 p95 | 변경 후 샘플 | 복귀 샘플 |
|---|---:|---:|---:|---:|
| 기본 | 25.1–28.2 ms | 0.47–0.74 ms | 0.09–0.10 ms | 0.07 ms |
| 그림자 | 58.4–61.9 ms | 0.04–0.05 ms | 0.02–0.03 ms | 0.02 ms |
| Color Balance | 3724–3884 ms | 0.005–0.007 ms | 3818–4077 ms | 3775–3917 ms |

Color Balance 측정 구간의 누적 managed 할당은 약 183.9 MiB, 종료 시 프로세스 working set은 약 481 MiB였다. 이는 해당 기능 단독 메모리나 시나리오 피크가 아니며 기존 프로세스/공유 자원도 포함한다. JSON의 peak는 프로세스 전체 수명 최대치다. 두 실행 모두 원본 복귀 색상 일치 검사를 통과했다.

성능 완료 아님: 조정 문서 최초/변경 샘플에 약 4초의 동기 정지가 재현됐다. CanvasRenderer가 조정 문서의 전체 합성을 캐시하며 스포이트와 화면 ViewportRenderer는 별도 인스턴스를 사용한다. 우선 화면에서 이미 생성한 동일 불변 문서 합성을 재사용할 경로를 검토하고, 캐시 미존재 시 응답성과 취소 처리를 개선해야 한다. 전체 색 공간/알파/효과 일치와 캐시 수명·문서 전환·Undo 복귀 검증이 필요하다. 이 측정은 실제 Mac 비교나 별도 Windows PC 검증을 대체하지 않는다.

## 화면 합성 캐시 공유

2026-10-07: ViewportRenderer가 소유한 CanvasRenderer를 스포이트의 1픽셀 샘플러에서도 사용한다. 캔버스 I/Alt 도구와 모달 색상 선택창 모두 이 경로에 연결했다. 화면 픽셀을 읽는 방식이 아니므로 확대/이동/체크무늬와 무관한 정규 문서 색상을 유지한다. UI 스레드 전용이며 샘플러는 빌린 렌더러를 해제하지 않고 ViewportRenderer가 최종 해제한다. 독립 CompositeColorSampler API는 기존 소유권을 유지한다.

검증: 코어 542개 및 WPF 회귀 통과. 화면 확대/이동 후 샘플, 샘플이 먼저 발생하는 문서 변경, 화면 재갱신, 원본 복귀, 범위 밖과 해제 후 호출을 검사했다. 공유 경로와 독립 경로의 색상이 일치한다.

4K 재측정(`artifacts/eyedropper-shared-benchmark.json`): 이미 화면을 합성한 문서의 첫 샘플은 기본 0.133ms, 그림자 0.104ms, Color Balance 0.047ms. 같은 실행의 독립 Color Balance 최초 샘플은 3798.70ms였다. 단, 공유 경로의 화면 준비에 3909.95ms가 소요되므로 최초 합성/캐시 없는 문서의 지연 자체가 해결된 것은 아니다. 실제 UI 이벤트 지연과 별도 PC 결과로 일반화하지 않는다. 조정 합성 최적화와 캐시 없는 경우의 비동기 처리/취소는 후속 성능 범위다.
배포 검증: artifacts/publish-shared-sampler 생성 및 격리 WPF 실행 1/1 통과. 원본 Mac/별도 PC 실기 보류 유지.
