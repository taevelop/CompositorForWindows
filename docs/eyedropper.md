# 스포이트 구현 현황

2026-10-07: 합성 색상 샘플러와 I 도구/브러시·지우개 Alt 임시 스포이트를 연결했다. 색상 비교 링과 열린 색상 선택창 샘플링은 아직 남아 있다.

원본 Document/ColorPalette.swift의 sampleCompositeColor는 화면의 체크무늬나 선택 윤곽을 제외한 보이는 레이어 합성 결과를 sRGB 단일 픽셀로 읽는다. 문서 좌표는 내림 처리하고 캔버스 밖 및 알파 0은 샘플 없음으로 처리한다. premultiplied 채널을 알파로 나누고 8비트 RGB로 반올림한다. 현재 레이어/평균 범위 선택은 이 원본 경로에 없다.

CompositeColorSampler는 화면/출력과 같은 CanvasRenderer와 1×1 출력 비트맵을 재사용한다. IDisposable로 비트맵/캔버스/렌더러 캐시를 정리한다. 조정과 효과의 내부 합성이 전체 문서 버퍼를 사용할 수 있으므로 1×1 출력이 전체 연산량이나 메모리까지 작다는 의미는 아니다. UI 연결 후 큰 문서 연속 샘플링의 지연과 메모리를 측정해야 한다.

검증: 코어 541개 및 기존 WPF 회귀 검사 통과. 소수 좌표 내림, 반투명 RGB 복원, 투명/범위 밖/NaN/무한대, 그룹 불투명도+마스크+숨긴 레이어의 전체 합성 픽셀 일치, 조정 문서 변경/원래 문서 복귀 시 캐시, 중복 Dispose 및 해제 후 호출 거부를 검사했다. 실제 Mac 색상 동등성은 보류다.

남은 연결: 색상 비교 링, 열린 색상 선택창 샘플링, 대형 문서 샘플링 지연/메모리 측정. 원본 Rendering/EditorCanvas.swift의 sampleColor는 팔레트 전경색을 갱신하며, 색상 선택창이 열렸다면 해당 선택창의 미리보기 색상만 갱신한다. 문서 픽셀/Undo는 변경하지 않아야 한다.

## 도구와 입력 연결

I 도구 또는 브러시/지우개에서 Alt+왼쪽 버튼으로 합성 색상을 전경색에 반영한다. 원본은 지우개가 브러시의 모드이므로 Windows의 별도 Eraser 도구도 Alt 샘플링을 지원한다. 누른 상태로 이동하면 연속 샘플링하며 다른 버튼이 입력을 가로채지 않는다. 선택 마스크와 무관하게 화면의 합성을 읽고, 마스크 편집 중에도 원본처럼 실제 전경색을 갱신하되 마스크 회색 농도는 바꾸지 않는다.

해제·Esc·캡처 상실·도구 전환은 입력 상태를 정리하며 마지막으로 읽은 색상을 유지한다. 문서 픽셀, 수정 상태, Undo는 바꾸지 않는다. 화면 좌표는 현재 확대/이동을 적용해 문서 좌표로 변환한다. I 및 Alt 입력은 기존 Ctrl+I 가져오기와 텍스트 입력 단축키를 유지한다. 커서는 현재 십자이며 원본 비교 링/전용 커서 완성은 후속 품질 범위다.

WPF 검사: 클릭/드래그, 투명/밖 영역의 이전 색상 보존, 버튼 조합, Alt 브러시/지우개, 취소/도구 전환, 확대/이동 좌표, 문서 스냅샷/Undo 불변성. Esc와 캡처 상실은 합성 WPF 이벤트로 검사한다. 실제 마우스·키보드 실기와 Mac 결과 비교는 대체하지 않는다.

최종 검증: 코어 541개, 확장 WPF 검사 및 I 도구 화면 정렬 확인 통과. artifacts/publish-eyedropper/Compositor.Windows.exe 생성 및 verify-portable.ps1 -Runs 1 통과. 별도 Windows/Mac 검증 보류 유지.

## 화면 합성 캐시 공유

2026-10-07: ViewportRenderer가 소유한 CanvasRenderer를 스포이트의 1픽셀 샘플러에서도 사용한다. 캔버스 I/Alt 도구와 모달 색상 선택창 모두 이 경로에 연결했다. 화면 픽셀을 읽는 방식이 아니므로 확대/이동/체크무늬와 무관한 정규 문서 색상을 유지한다. UI 스레드 전용이며 샘플러는 빌린 렌더러를 해제하지 않고 ViewportRenderer가 최종 해제한다. 독립 CompositeColorSampler API는 기존 소유권을 유지한다.

검증: 코어 542개 및 WPF 회귀 통과. 화면 확대/이동 후 샘플, 샘플이 먼저 발생하는 문서 변경, 화면 재갱신, 원본 복귀, 범위 밖과 해제 후 호출을 검사했다. 공유 경로와 독립 경로의 색상이 일치한다.

4K 재측정(`artifacts/eyedropper-shared-benchmark.json`): 이미 화면을 합성한 문서의 첫 샘플은 기본 0.133ms, 그림자 0.104ms, Color Balance 0.047ms. 같은 실행의 독립 Color Balance 최초 샘플은 3798.70ms였다. 단, 공유 경로의 화면 준비에 3909.95ms가 소요되므로 최초 합성/캐시 없는 문서의 지연 자체가 해결된 것은 아니다. 실제 UI 이벤트 지연과 별도 PC 결과로 일반화하지 않는다. 조정 합성 최적화와 캐시 없는 경우의 비동기 처리/취소는 후속 성능 범위다.
배포 검증: artifacts/publish-shared-sampler 생성 및 격리 WPF 실행 1/1 통과. 원본 Mac/별도 PC 실기 보류 유지.

## Color Balance 커널 병렬 실행

2026-10-07: 262,144픽셀 이상인 색상 균형 조정을 최대 8개 작업으로 분할한다. 원본 C 계산식과 반올림을 변경하지 않고, 한 번 pin한 RGBA 배열의 겹치지 않는 픽셀 범위를 호출한다. 모든 작업이 종료된 후 pin을 해제한다. 작은 이미지와 단일 작업 환경은 기존 직렬 경로를 유지한다. 별도 이미지 복사나 native 런타임 의존성을 추가하지 않는다.

검증: 코어 544개 및 WPF 회귀 통과. 무작위 유효 premultiplied RGBA 262,161픽셀을 3/8개 작업으로 분할하고 luminosity 보존 켜기/끄기 각각 원본 직렬 커널과 전체 바이트 일치를 검사했다.

같은 4K 벤치마크 2회: Color Balance 최초 샘플 767.74–783.73ms, 화면 최초 합성 749.27–783.67ms, 준비된 화면의 샘플 0.022–0.027ms. 이전 직렬 화면 합성 3909.95ms 대비 이 PC에서 약 80% 감소했다. 파일: artifacts/eyedropper-parallel-benchmark.json 및 eyedropper-parallel-repeat.json. 프로세서 수/부하에 따라 달라지며 실제 WPF 표시 지연을 측정한 것은 아니다. 약 0.8초의 동기 최초 합성은 여전히 남아 있어 캐시 미존재 시 응답성/취소를 완료로 처리하지 않는다. 다른 조정 종류와 4K 브러시 전체 성능으로 일반화하지 않는다.
배포: artifacts/publish-parallel-balance 생성, 격리 WPF 실행 1/1 통과. 실제 Mac 및 별도 Windows PC 실기 보류 유지.

## 백그라운드 합성 준비 기반

2026-10-07: PreparedDocumentRender.CreateAsync는 별도 작업 스레드에서 자체 CanvasRenderer를 준비하고, 완료된 캐시의 소유권을 UI ViewportRenderer에 한 번 전달한다. 1픽셀 샘플 경로로 정규 조정 합성을 만들므로 별도 전체 출력 이미지를 유지하지 않는다. 다른 문서 스냅샷/해제된 준비 결과/해제된 화면 렌더러의 설치를 거부한다. 교체 시 기존 샘플러·캐시를 해제하고 다음 화면은 전체 갱신한다. 결과를 채택하지 않으면 Dispose해야 한다.

취소는 시작 전 및 합성 직후 확인하며, 네이티브 커널 중간 선점 취소는 아니다. 실패/취소 시 작업 소유 렌더러를 해제한다. 화면과 worker는 같은 renderer를 동시에 사용하지 않는다.

현재는 기반 API와 소유권/문서 일치/사전 취소/중복 해제/화면 렌더링/색상 검사를 추가한 단계다. 실제 WPF의 대형 조정 문서에 연결, 요청 합치기, 늦은 결과 폐기, 진행 표시, 스포이트 대기/취소, 문서 전환·창 종료 및 Dispatcher 응답성 검사가 남았다. UI 지연 개선 완료로 계산하지 않는다.
기반 단계 검증: 경고/오류 0, 코어 546개 및 기존 WPF 회귀 통과. 이 단계는 새 배포 패키지를 생성하지 않았으며, UI 연결 후 패키지 검증을 수행한다.

## 대형 조정 문서의 비동기 화면 연결

2026-10-07: 100만 픽셀 이상이며 조정 레이어가 있는 문서는 Paint에서 동기 합성 대신 백그라운드 준비를 요청한다. 준비 중에는 Preparing image 문구를 표시한다. 한 작업만 실행하고 동일 문서 요청은 합친다. 새 스냅샷은 진행 중 작업의 취소를 요청하고 완료 후 최신 요청만 계산한다. Session 교체/작은 문서 전환/캔버스 Dispose는 요청을 취소한다. 결과는 현재 Session.Document와 참조가 일치할 때만 설치한다. 작업 실패는 알리고 같은 문서의 무한 재시도를 막는다.

캔버스/선택창 스포이트도 준비되지 않은 큰 조정 문서에서 동기 계산하지 않고 샘플 없음으로 반환한다. 준비 후 포인터 이동/다음 클릭으로 샘플링한다. 네이티브 계산 중 취소는 계산 종료 후 폐기 방식이며, 작업 스레드에서도 CPU/메모리는 사용한다. 준비 중 이전 화면 유지나 마지막 스포이트 위치 자동 재시도는 아직 지원하지 않는다.

검증: 코어 546개 및 확장 WPF 회귀 통과. 1000×1000 조정 문서의 비동기 시작, 같은 요청 중복 방지, 준비 중 샘플 차단, Dispatcher Input 호출, 새 문서 결과와 색상 일치, 종료 중 결과 폐기를 검사했다. 물리 입력 지연의 백분위/4K 연속 편집 메모리·프레임률은 측정하지 않았으며 성능 영역 전체 완료가 아니다. 작은 문서 및 조정 없는 문서는 기존 동기 경로다.
배포: artifacts/publish-async-composite 생성 및 격리 WPF 실행 1/1 통과. 실제 Mac/별도 Windows PC 실기 보류 유지.

## 준비 중 마지막 스포이트 위치 적용

2026-10-07: SampleCompositeAsync는 요청 당시 세션과 문서 스냅샷을 고정하고 비동기 합성이 끝난 뒤 동일한 경우만 샘플링한다. 캔버스는 위치 요청 번호로 이전 결과를 폐기한다. 정상 버튼 해제는 마지막 위치 요청을 유지하고, CancelInteraction은 이를 무효화한다. 캔버스 종료 및 세션/스냅샷 교체도 늦은 적용을 막는다.

모달 샘플 창은 마지막 위치 계산을 기다린 뒤 확정하고, 닫기/취소 이후 색상 미리보기를 갱신하지 않는다. 기다리는 동안 새 드래그가 시작되면 이전 해제가 새 동작을 닫지 않는다. 정상적인 투명 픽셀 처리는 기존처럼 직전 유효 색상을 유지한다.

검증에 캐시 없는 큰 문서에서 포인터 이동 후 해제 위치 적용, 취소된 요청의 전경색 변경 차단을 추가했다. 실제 물리 마우스/키보드 타이밍과 입력 지연 백분위는 아직 측정하지 않았다. 이후 연속 편집·메모리·모달 창의 실제 DPI 입력 검증을 이어간다.
최종 검증: 경고/오류 0, 코어 546개 및 확장 WPF 회귀 통과. artifacts/publish-deferred-sampling 생성 및 격리 실행 1/1 통과. 외부 Mac/별도 PC 검증 보류 유지.

## WPF 연속 요청/메모리 측정

2026-10-07: `Compositor.Windows.exe --render-benchmark <절대 JSON 경로>` 전용 실행을 추가했다. 숨겨진 실제 MainWindow/EditorCanvas에서 4K Color Balance 값을 20ms 간격으로 5회 바꾸는 묶음을 8번 실행한다. 16ms Input 우선순위 DispatcherTimer의 실제 호출 간격, 묶음 최종 화면 준비 시간, 프로세스 working set/managed heap을 기록한다. 마지막 문서의 색상은 독립 렌더러와 비교한다. 앱 기본 시작이나 일반 smoke 시간 제한은 변경하지 않았다.

산출물: artifacts/async-render-benchmark.json, artifacts/async-render-benchmark-repeat.json. 두 실행 모두 최신 스냅샷 준비 및 최종 색상 일치 검사를 통과했다. 이 간격은 OS 스케줄링·GC·WPF 처리 비용을 포함하며 물리 입력 지연 또는 가시 화면 프레임률이 아니다. 짧은 8묶음 결과로 메모리 누수 여부를 판정하지 않는다. 큰 취소 작업의 중간 중단/할당 감소, 더 긴 메모리 안정성 검사 및 물리 입력은 성능 잔여로 유지한다.
