# 공식 화면을 기준으로 한 Windows 도구 UI

2026-10-06. [공식 다운로드 페이지](https://robbietilton.com/compositor)의 [히어로 제품 화면](https://robbietilton.com/static/compositor/hero.png)과 저장소의 Mac UI 소스를 비교했다. 이전 Windows 개선은 입력 컨트롤만 바꾸고 가로 도구 막대와 속성 중심 패널을 유지했으므로, 이번에는 화면 구조도 변경했다. 사용자가 선택한 강조색은 차분한 블루다.

## 분석과 반영

| 공식 화면에서 확인한 구성 | Windows 변경 |
|---|---|
| 왼쪽의 좁은 세로 아이콘 도구 레일 | 56 DIP 레일에 Move / Brush / Eraser / Hand 벡터 아이콘, 툴팁·접근성 이름·V/B/E/H 유지 |
| 상단의 도구별 옵션 영역 | 도구 이름 옆에 크기·경도·불투명도·색상 옵션을 배치하고 Move/Hand에는 조작 안내 표시 |
| 어두운 문서·캔버스 중심 화면 | 문서 이름·수정 상태, 가져오기·PNG 출력·Fit·100%를 얇은 상단 바에 배치 |
| 오른쪽 상단의 합성 모드·불투명도, 그 아래 레이어 목록 | 레이어 목록을 패널 중심에 고정하고 세부 속성·마스크·그룹·효과를 Selected layer 안으로 이동 |
| 레이어 패널 크기 조절 | 캔버스와 패널 사이 경계를 드래그해 245–420 DIP로 조절 |
| 색상 면 옆의 세로 색조 막대와 RGB/HEX | 선택 창을 가로 배치로 재구성하고 RGB 검증·현재/새 색상·팔레트·적용/취소 제공 |
| 제한적으로 사용되는 푸른 강조색 | 선택 버튼·레이어·슬라이더·포커스·색상 적용 버튼을 공통 블루 리소스로 통일 |

근거가 되는 Mac 소스는 [ContentView](../macOS/Compositor/ContentView.swift), [BrushControls](../macOS/Compositor/UI/BrushControls.swift), [ColorPickerSheet](../macOS/Compositor/UI/ColorPickerSheet.swift)다. 원본 브러시 크기는 숫자 입력이며 경도·불투명도는 슬라이더와 숫자를 병행한다. Windows의 크기 슬라이더는 사용 편의를 위해 유지했다.

공식 화면의 모든 도구가 Windows에 구현되었다는 뜻은 아니다. 레일에는 실제 지원하는 4개 도구만 표시한다. Mac의 다중 문서 탭·캔버스 스포이트·추가 도구·레이어 썸네일을 흉내 낸 비활성 UI는 추가하지 않았다. 상단 문서 표시는 현재 문서 하나를 나타내며 탭 전환 기능이 아니다. `macOS/` 원본 파일과 이미지 처리 알고리즘은 변경하지 않았다.

## 색상과 사용법

- UI 강조색: `Accent = #6C9AE0`, 선택 배경: `AccentMuted = #293A52`. [App.xaml](../Compositor.App/App.xaml)에 공통 정의한다. 이전 민트 강조색을 제거했다.
- 그림에 사용하는 색상은 테마와 독립적이다. 새 세션의 초기 전경색은 중립적인 `#202020`이며, 사용자가 선택한 색이나 저장된 이미지 픽셀을 테마색으로 치환하지 않는다.
- 도구는 왼쪽 아이콘 또는 V/B/E/H로 선택한다. 상단 Color의 **Choose color…** 또는 레일 아래 색상 견본을 누르면 같은 색상표가 열린다. HEX/RGB 직접 입력은 색상표 안에서 제공한다. 마스크 편집 중에는 전경색 선택을 비활성화한다.
- Size, Hardness, Opacity는 슬라이더 및 숫자 입력을 지원한다. 숫자는 Enter 또는 포커스 이동으로 확정한다. 범위 밖 값은 보정하고 잘못된 초안은 마지막 정상 값으로 복원한다. Enter 후 캔버스로 포커스를 돌린다.
- 마스크 Brush에서는 농도와 Black / White를 표시한다. 지우개는 기존대로 픽셀 또는 마스크를 지운다.
- 색상 면은 좌우 채도·상하 명도, 세로 막대는 색조를 조절한다. 방향키는 면에서 1%, Shift+방향키는 10%씩 조절한다. RGB는 0–255 정수, HEX는 6자리이며 잘못된 입력 중에는 적용이 차단된다.
- Use color는 적용, Cancel/Esc/창 닫기는 원래 브러시 색 보존이다. 불투명도는 색상 대신 브러시 Opacity로 조절한다.
- 오른쪽 레이어 불투명도 슬라이더는 초안을 변경하며 **Apply properties**로 적용한다. 기존 속성 적용과 Undo 동작을 유지한다.
- 세부 속성은 **Selected layer**를 펼친다. 작은 창에서는 이 영역이 스크롤되며 레이어 목록의 공간을 유지한다.
- 도구·브러시 설정 변경은 문서 편집 이력을 만들지 않는다.

이번 변경은 도구·패널 배치와 색상 선택 UI에 집중한다. 개별 효과/조정 창 전체를 Mac과 동일하게 재작성한 것은 아니며, 색상 선택기는 모달 창이다.

## 검증

`build.ps1 -Test`로 Release 빌드(경고·오류 0), xUnit 260개와 기존 및 확장 WPF 검사를 통과했다.

추가 확인: RGB 범위 검증, 색조·HEX 동기화, 세로 도구 레일 위치, 1000×650 창의 옵션 바 높이와 펼친 속성 영역/레이어 목록, 어두운 합성 모드 팝업 열기, 레이어 불투명도 초안·적용·Undo, 블루 공통 리소스. 결과는 `artifacts/ui-smoke.tools.json`이다.

실제 렌더링 이미지 `ui-smoke.png`, `ui-smoke.tools.compact.png`, `ui-smoke.tools.picker.png`를 확인했다. self-contained 배포본은 `verify-portable.ps1 -Runs 1`로 복사 실행·WPF 기능 및 패키지 내부 DLL 로딩을 검증한다. 기존 사용자 마우스·DPI 실기 기록은 이전 UI에 대한 결과이므로 이번 배치의 실제 사용성 확인과 구분한다.

## 2026-10-06 UI 회귀 수정

- 메뉴는 자체 템플릿으로 일반·강조·열림·비활성 상태와 구분선을 통일했다. 강조 배경은 `#293A52`, 비활성 글자는 `#777E89`이며 기본 Windows 메뉴의 흰 테두리/청록 강조가 섞이지 않는다.
- 옵션 영역을 고정 제목 열과 내용 열로 분리해 Move/Brush/Eraser/Hand 전환 시 제목과 캔버스 시작 위치를 유지한다.
- 상단 Color에 견본이 포함된 **Choose color…** 버튼을 제공하고 레일 견본과 동기화한다. 마스크 모드에서는 색상 대신 농도·Black/White를 제공한다.
- 캔버스 선택 외곽선에 남아 있던 민트도 블루로 통일했다.
- WPF 검사에 네 도구의 실제 좌표 비교, 두 색상 버튼으로 모달 열기·적용, 다섯 메뉴의 팝업·키보드 강조·비활성 상태 검사를 추가했다. 메뉴 팝업은 별도 PNG로 렌더링해 확인했다. 기존 슬라이더·마스크·좁은 창·레이어 불투명도 검사도 유지한다.
- 실행 중인 기존 앱을 보존하도록 별도 배포 경로를 지원한다: `./build.ps1 -Publish -PublishDirectory artifacts/publish-ui-fix`, `./verify-portable.ps1 -Runs 1 -PackageDirectory (Join-Path $PWD artifacts/publish-ui-fix)`.
- 검증: Release 빌드 경고·오류 0, xUnit 260개 및 확장 WPF 검사 통과. 새 UI의 사용자 마우스 실기 확인은 별도다.
