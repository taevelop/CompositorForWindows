# 선택 자동 스크롤

원본 Rendering/EditorCanvas.swift의 marqueeAutoscrollDelta / stepMarqueeAutoscroll과 호출 지점을 대조했다.

- 사각형·타원 선택을 그리거나 기존 선택 윤곽을 드래그할 때 화면 가장자리에서 캔버스가 이동한다.
- 가장자리 안쪽 12 DIP에서 시작하고 60Hz 타이머의 한 틱당 2 + 거리 × 0.4 DIP, 최대 40 DIP로 이동한다. 줌과 무관하게 화면 속도를 계산하며 문서 좌표는 현재 줌으로 환산한다.
- 정지한 포인터 아래의 문서 좌표를 다시 구하여 선택 끝점/윤곽을 갱신한다. 드래그 시작점은 그대로 유지하고 한 번의 Undo로 확정한다.
- 원본과 동일하게 자유 올가미·다각형 생성, 선택 픽셀 이동, 크롭·브러시·손 도구에는 적용하지 않는다. 올가미 도구에서도 기존 선택 윤곽 이동은 대상이다.
- 중앙으로 돌아오기, 버튼 놓기, 편집 종료, Esc/취소, 도구 전환, 마우스 캡처 상실, 창 비활성화와 Unloaded/Dispose에서 정지한다. 문서 변경 후 트랜잭션이 사라져도 정지한다.
- 취소는 선택을 복원하며 이동한 뷰포트는 유지한다.

## 검증

코어 468개 검사에 방향별 시작 거리·속도 상한·비정상 좌표 검사를 추가했다.
WPF에서는 실제 캔버스/세션에 결정적인 틱을 주입하여 끝점 추종, 고정 시작점, 확대 배율, 윤곽 크기 보존, 단일 Undo, 버튼/캡처/도구/취소 정지를 검사한다. 실제 Dispatcher 타이머가 캡처 없는 입력에서 정지하는 경로도 검사한다.
하드웨어 마우스를 누른 채 화면 밖에 오래 머무르는 실기 검사를 자동 검증했다고 주장하지 않는다. 선택/큰 페더 CPU 작업이 무거울 때의 실효 틱 속도와 지연 측정은 품질 잔여다.

실행 패키지: artifacts/publish-selection-scroll/Compositor.Windows.exe.

./build.ps1 -Test: 경고/오류 0, 코어 468개 및 실제 WPF 검사 통과. verify-portable.ps1 -Runs 1 격리 실행 통과. 개발 PC의 공백 경로·제한 PATH·공유 런타임 미사용 검사이며 별도 Windows PC 검증을 대체하지 않는다.

2026-10-07: 새 문서 드롭 회귀 실행 중 기존 50ms 대기 후 Dispatcher 타이머 종료 검사가 한 번 실패했다. Task.Delay 완료와 Input 우선순위 타이머 처리 순서를 동일하게 가정하지 않도록 대기 후 ApplicationIdle Dispatcher 작업까지 처리한 다음 같은 종료 조건을 검사한다. 실제 StepSelectionAutoScroll의 종료 구현과 전체 WPF 30초 제한은 변경하지 않았다. 이 보완으로 다른 모든 간헐 실패 원인이 해결됐다고 판단하지 않는다.
