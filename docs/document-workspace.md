# 문서 탭 구현 현황

2026-10-07: 작업 공간 모델 기반 구현. 아직 MainWindow의 단일 문서 UI에는 연결하지 않았다.

- 탭마다 독립 EditorSession, Undo/Redo, 선택, 수정 여부 및 저장 경로를 유지한다.
- 같은 정규화 경로의 열기는 기존 탭을 선택하며 수정 내용을 교체하지 않는다. 링크/정션의 실제 파일 동일성 비교는 미구현이다.
- 로드 데이터 검증을 통과한 세션만 추가한다. 복구본은 저장 경로 없는 수정된 문서로 취급한다.
- 진행 중 편집의 전환/닫기와 미저장 문서의 무단 닫기를 막는다. 마지막 탭을 닫으면 새 빈 문서를 만든다.
- 종료 확인 순서는 현재 탭부터 나머지 탭 순서다. 실제 저장/폐기/취소 질문은 UI 책임이다.
- ValidateSaveDestination을 파일 쓰기 전에 호출하고, 저장 성공 후 RecordSaved를 호출해야 한다. 호출자는 그 사이 작업 공간 변경을 막아야 한다. 사전 검증은 수정 상태나 경로를 변경하지 않는다.

검증: 코어 533개 회귀 검사 통과. 기존 WPF 검사도 기반 모델 단계에서 통과했으나 문서 탭 UI의 검증 증거는 아니다.

남은 연결: 탭 표시/선택/닫기, 새 문서·열기·저장·복구·앱 종료, 탭별 확대/이동 및 계층 접힘 상태, 비동기 결과의 대상 문서 고정, 실패/취소/저장 충돌 UI 회귀 검사. 이 단계는 문서 탭 기능 완료로 계산하지 않는다.
