# 문서 탭 구현 현황

2026-10-07: 작업 공간 모델과 MainWindow 탭 UI, 새 문서/열기/저장/복구/닫기를 연결했다.

## 현재 동작

- 새 문서와 프로젝트 열기는 새 탭을 추가한다. 기존 문서의 미저장 편집을 버리지 않는다.
- 탭마다 독립 EditorSession, Undo/Redo, 선택, 수정 여부 및 저장 경로를 유지한다.
- 같은 정규화 경로의 열기는 기존 탭을 선택하며 수정 내용이나 이력을 교체하지 않는다. 디스크에서 다시 읽으려면 해당 탭을 닫고 연다.
- 탭 전환 시 확대/이동 위치와 그룹 접힘 상태를 보존한다. 변형은 확정하고 진행 중 포인터 동작과 크롭 초안은 취소한다.
- 로드 데이터 검증을 통과한 세션만 추가한다. 실패한 열기는 기존 문서와 이력을 보존한다. 복구본은 저장 경로 없는 수정된 새 탭이다.
- 탭의 × 버튼은 미저장 문서에 저장/폐기/취소를 묻는다. 마지막 탭을 닫으면 새 빈 문서를 만든다.
- 앱 종료는 현재 탭부터 나머지 탭을 확인한다. 비활성 탭의 미저장 내용도 해당 탭으로 이동해 확인하며 취소/저장 실패 시 창을 유지한다.
- ValidateSaveDestination을 파일 쓰기 전에 호출하고, 저장 성공 후 RecordSaved를 호출한다. 다른 탭이 연 경로는 저장을 거부한다. 파일 작업 중 busy 상태는 탭 전환/닫기를 차단한다.

## 검증

코어 533개, 확장한 실제 WPF 검사 통과. 탭별 문서/Undo 분리, 확대 위치 복원, 같은 파일 열기의 이력 보존, 탭 닫기 후 실제 디스크 재열기, 닫기 취소/폐기, 비활성 미저장 탭의 앱 종료 취소를 검사했다. 기존 효과/조정/마스크 등의 저장 왕복 검사도 탭 닫기 후 재열기로 변경해 실제 로드 검증을 유지했다.

artifacts/ui-smoke.workspace.png에서 활성 탭의 블루 표시, 문서명/수정 표시와 닫기 버튼을 확인했다. 기존 단일 문서 검사 종료는 모든 테스트 탭을 정리하도록 갱신했다. 물리 마우스나 외부 장비 검증을 대신하지 않는다.

## 잔여

- 프로젝트 디렉터리 드롭, 캔버스 위치로 직접 레이어 전달, 여러 탭의 접근성/오버플로 품질. 탭 재정렬은 Windows 확장 후보이며 원본 필수 동작으로 확인되지 않았다.
- 추가 도구가 구현될 때 해당 도구 설정도 탭별 상태에 포함해야 한다. 전경/배경 팔레트 등 미구현 도구는 별도 잔여 범위다.
- 링크/정션의 실제 파일 동일성 비교, 여러 대형 문서를 연 상태의 메모리/렌더링 성능.
- 그룹 접힘 복원의 복합 실기와 다양한 DPI에서의 탭 조작.
- 실제 Mac 왕복과 별도 Windows PC 검증은 사용자 보류 유지.

배포 확인: artifacts/publish-document-tabs/Compositor.Windows.exe 생성 및 verify-portable.ps1 -Runs 1 통과. 개발 PC의 공유 런타임 차단/공백 경로 검사이며 별도 PC 검증은 아니다.

## 탭별 도구 설정과 단축키

원본 macOS/Compositor/Document/EditorSession.swift의 brushSettings, selectionModeChoice, cropRatioChoice 등 세션별 설정을 대조했다. Windows에서 구현된 도구 선택, 브러시 크기/경도/불투명도/색상, 마스크 농도, 선택 연산/안티앨리어싱/중심 기준, 크롭 비율/스냅을 탭마다 보관한다. 새 탭은 Windows 앱의 초기 기본값으로 시작한다. 이 UI 상태는 문서 수정이나 Undo를 생성하지 않고 .comp에 저장하지 않는다. 크롭 초안은 이전과 같이 전환 시 취소한다.

Ctrl+Tab / Ctrl+Shift+Tab은 다음/이전 탭을 순환하고 Ctrl+W는 현재 문서 닫기를 요청한다. View 메뉴에도 표시했다. 문서 단축키는 텍스트 입력의 일반 편집 단축키보다 먼저 처리한다. 텍스트의 Undo/Delete 처리는 유지한다.

코어 533개 및 확장 WPF 검사 통과. 서로 다른 도구 설정의 복원, 새 문서 기본값, 크롭 초안 비전파, 다음/이전 탭 명령, Ctrl+W 명령의 미저장 취소를 검사했다. 단축키 검사는 실제 창의 명령 처리 함수를 제어된 키/수정키 인자로 호출한 것이며 물리 키보드 입력 검증은 아니다.

배포본 artifacts/publish-tab-tools/Compositor.Windows.exe 및 verify-portable.ps1 -Runs 1 통과. 별도 Windows/Mac 실기는 보류다.

## 많은 탭의 표시와 접근성

탭 갱신 시 기존 버튼을 재사용하여 일반 문서 갱신이 포커스 대상 컨트롤을 제거하지 않게 했다. 긴 문서명은 말줄임하며 전체 경로는 도구 설명에서 확인한다. 활성 문서가 바뀌면 레이아웃 이후 해당 탭을 자동으로 보이게 한다. 활성/미저장 상태를 선택 버튼의 접근성 이름에 포함하고 닫기 버튼도 대상 문서명을 알린다.

코어 533개와 WPF 검사 통과. 10개 탭 추가 후 실제 ScrollViewer의 넘침, 마지막 활성 탭 전체 노출, 첫 탭으로 돌아갈 때 왼쪽 스크롤 복원을 검사했다. 컨트롤 동일성/기존 포커스 유지 및 접근성 이름도 검사했다. 실제 화면 읽기 프로그램과 다양한 DPI 조작은 미검증이며 탭 재정렬은 아직 잔여다.

배포본 artifacts/publish-tab-navigation/Compositor.Windows.exe 생성 및 verify-portable.ps1 -Runs 1 통과. 별도 장비 검증은 보류 상태다.

## 원본 재대조와 탭 대상 이미지 드롭

원본 ProjectTabs.swift 및 ProjectWorkspace.swift를 재대조한 결과 탭 순서 변경은 확인되지 않았고, 문서 탭/새 캔버스에 이미지와 레이어를 드롭하는 동작이 구현돼 있었다. 앞선 재정렬 잔여 표기는 원본 필수 기능이라는 뜻으로 해석하지 않는다. 재정렬은 확장 후보로 남기고 원본의 드롭 경로를 우선 이식한다.

Windows에서는 PNG/JPEG 등의 ImageCodec 지원 이미지 파일을 기존 문서 탭으로 드롭하면 그 탭을 선택해 레이어로 가져온다. 탭 프레임이 드롭을 처리하여 창의 현재 문서 가져오기 경로로 다시 전파되지 않게 했다. 작업 중에는 거부하고, 정상 대상은 파란 테두리로 표시한다. 읽기 실패 시 대상 탭은 선택된 상태지만 픽셀/레이어/Undo는 변경하지 않는다. 프로젝트 디렉터리는 아직 지원하지 않는다. 내부 레이어 전달은 아래 후속 구현으로 연결했다. 새 캔버스 드롭은 아래 후속 구현으로 연결했다.

코어 533개 및 WPF 검사 통과: 비활성 대상 탭 선택/레이어 추가, 이전 문서 불변성, 단일 Undo, 여러 파일 중 하나 실패 시 부분 가져오기 방지, busy 차단. 실제 창의 드롭 명령 경로를 호출한 검사이며 Explorer에서의 물리 OLE 드래그, 경계 강조 및 화면 읽기 프로그램 실기는 별도 미검증이다.

배포본 artifacts/publish-tab-drop/Compositor.Windows.exe 생성 및 verify-portable.ps1 -Runs 1 통과. 별도 Windows/Mac 검증 보류 유지.

## 새 캔버스 이미지 드롭

탭 줄의 + New는 클릭하면 새 캔버스 크기 입력을 열고, 이미지 파일을 드롭하면 파일마다 새 문서를 만든다. 원본 ProjectWorkspace.receive의 파일별 새 탭 규칙을 따른다. 캔버스는 이미지 픽셀 크기이고 이미지 레이어는 (0,0)에 원래 크기로 놓인다. 저장 경로 없는 수정된 문서이며 가져오기를 한 번의 Undo/Redo로 취소/복원할 수 있다.

각 파일은 비동기로 읽은 뒤에만 탭을 추가한다. 중간 파일이 읽기에 실패하면 오류를 알리고 빈 탭 없이 다음 파일을 처리한다. 앞서 성공한 문서는 유지한다. 기존 탭의 여러 이미지 가져오기는 기존처럼 하나라도 실패하면 전체 추가를 취소한다. 프로젝트 디렉터리, RAW 전용 처리, 문서 간 레이어 전달은 별도 잔여다.

WPF 검사에 정상/실패/정상 파일 묶음의 2개 탭 생성, 크기/원점/레이어 수, 수정 여부/저장 경로/이력, 이전 문서 불변성, Undo/Redo를 추가했다. 실제 Explorer 마우스 드롭과 여러 대형 이미지의 전체 메모리 측정은 아직 미검증이다.

검증 결과: 코어 533개, 실제 WPF 회귀, 화면 배치 확인 통과. artifacts/publish-new-image-tabs/Compositor.Windows.exe 생성 및 verify-portable.ps1 -Runs 1 통과. 실제 마우스와 별도 Windows/Mac 검증은 통과로 처리하지 않는다.

## 문서 간 레이어 전달

레이어 패널에서 다른 문서 탭 또는 + New로 드래그하면 원본을 유지하고 레이어를 복사한다. 선택된 그룹의 자식을 포함하고 부모/자식 중복 선택은 한 번만 복사한다. 새 ID로 내부 부모 관계를 다시 연결하며 외부 부모와는 분리한다. 이름·표시·불투명도·합성·효과·조정·현재 지원하는 연결 마스크·회전/뒤집기를 유지한다. 이미지/마스크 타일은 불변 데이터를 공유한다.

원본 ProjectWorkspace.copyLayer처럼 드래그의 기준 레이어 중심을 대상 문서 중앙으로 이동한다. 여러 선택은 활성 선택 레이어를 기준으로 같은 이동량을 적용한다(원본 단일 행 전달의 다중 선택 확장). 새 문서는 원본 문서 크기로 만든다. 전달 전에 문서/계층/좌표/픽셀 예산/레이어 수를 검증한다. 대상 문서만 한 번의 Undo가 생기고 복사된 루트를 선택한다. 동일 문서, Alt 드래그, 외부/오래된 내부 드래그 데이터, 작업 중인 문서는 전달을 거부한다.

검증: 코어 537개 통과. 그룹 계층/좌표/숨김/불투명도/회전/마스크 공유, 외부 부모 분리, 잘못된 목적지/레이어 수 제한, 저장 왕복, Undo/Redo 검사. WPF 경로에서는 기존/새 탭 전달, 원본 불변성, 같은 탭/Alt/위조 데이터 거부, 중심 배치 및 이력을 검사했다. 실제 OLE 마우스 조합과 강조 표시, 대형 그룹 메모리/지연은 별도 미검증이다.

현재는 탭 중심 드롭을 지원한다. 캔버스의 특정 위치에 직접 드롭, 원본의 미지원 독립/라이브 마스크 베이킹, 프로젝트 폴더 드롭은 잔여 범위다. 서브트리만 복사하므로 복사하지 않은 외부 부모의 합성/불투명도를 굽지는 않으며 원본의 전달 규칙을 따른다.

배포본 artifacts/publish-layer-transfer/Compositor.Windows.exe 생성 및 verify-portable.ps1 -Runs 1 통과. 실제 별도 Windows/Mac 검증은 사용자 보류 유지.
