# 핵심 MVP 완료 판정

2026-10-06. Windows 11 x64를 대상으로, 최초 MVP 범위의 구현과 실제 사용 검증을 구분한다. 기능 확장보다 아래 완료 조건을 먼저 닫는다. Mac 원본은 수정하지 않았다.

## 범위와 현재 판정

핵심 기능은 구현됐으며 로컬 자동 검증을 통과했다. **외부 장비에서의 실기 검증이 남아 있어 MVP 전체 완료로 판정하지 않는다.** 기존 진행률 추정 90/100에서 실제 저장 프로세스 중단·복구 검증 2점과 사용자 확인에 따른 마우스·다중 DPI 실기 4점을 완료하여 **96/100, 잔여 4/100**으로 관리한다. 이는 합의한 항목의 관리용 가중치이며 코드 줄 수나 실측 공수 비율이 아니다.

| 핵심 범위 | 구현 및 로컬 자동 검증 | 최종 확인 |
|---|---|---|
| Windows 실행, PNG/JPEG 가져오기·내보내기 | 완료 | 별도 Windows PC |
| 레이어 추가·삭제·순서·표시·불투명도·기본 7개 합성 모드 | 완료 | Mac 왕복 잔여 · 실기 사용자 확인 |
| 이동·크기·회전, 캔버스 확대·이동 | 완료 | 사용자 실기 확인 완료 |
| 브러시·지우개, 타일 경계, Undo/Redo·취소 | 완료 | 사용자 실기 확인 완료 |
| `.comp` 저장·열기, 미지원 파일 거부 | 완료 | 실제 Mac 왕복 |
| 저장 실패·실제 프로세스 중단·복구 | 완료 | 전원/물리 디스크 장애는 이 검증의 범위 밖 |
| 4K/800px 브러시, 반복 편집, 배포 폴더 실행 | 로컬 기준 통과 | 별도 PC 및 장시간 수동 사용 |

마스크·그룹·Exposure·Levels·Curves·색상 오버레이는 기존 구현의 회귀 검사에 포함되지만 핵심 MVP의 잔여 점수를 늘리거나 줄이지 않는다. PSD·AI·RAW·편집 가능한 텍스트·추가 효과·GPU 구현·설치 프로그램·서명·자동 업데이트는 이번 완료 범위에 넣지 않는다. GPU 경로 변경은 성능 근거가 있을 때 별도 결정한다.

## 재현 명령과 결과

저장소 루트의 PowerShell에서 실행한다. 실행 중인 사용자 앱을 자동 종료하지 않으므로 먼저 앱을 닫는다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File verify-mvp.ps1
```

이 명령은 Release 빌드, xUnit, 숨김 WPF 검증, 다층 4K 측정, self-contained 배포, 실제 저장 중단, 1,200회 반복 편집, 복사한 배포본 WPF 검사 3회를 실행한다. 각 기능 실패와 성능 기준 초과는 오류 종료하며, 성공 보고서도 `mvpAccepted=false`와 남은 실기 항목을 기록한다. RID 배포가 바꾼 NuGet 잠금 파일은 실행 전 바이트로 복구한다.

| 결과 | 파일 | 확인 내용 |
|---|---|---|
| 빌드/회귀 | 콘솔, `artifacts/ui-smoke.*.json` | Release 경고·오류 0, xUnit 260개, 기본 및 확장 기능 WPF 경로 |
| 실제 중단 복구 | `artifacts/save-crash-validation.json` | 신규/덮어쓰기 × 4단계, 총 8개 |
| 반복 편집 | `artifacts/mvp-soak-validation.json` | 1,200회, 저장 왕복/PNG/JPEG 각 48회, 문서 초기화 6회 |
| 성능 | `artifacts/stability-benchmark.json` | 4K 소스 1/3/6개, 800px 브러시 각 120점 × 2스트로크 |
| 복사한 배포본 | `artifacts/portable-validation.json` | WPF 실행 3회와 패키지 내부 CLR·Skia·C DLL 경로 |
| 종합 | `artifacts/mvp-acceptance.json` | 로컬 자동 검증 합격, 별도 실기 미완료 |

자동 검증 산출물은 `artifacts/`에 보존하며 Git에는 넣지 않는다. 실패 시 해당 명령이 오류 종료하며 새 실행의 중단/반복/배포/종합 성공 보고서는 이전 실행 결과를 남기지 않도록 제거한다. 과거 결과가 필요한 경우 실행 전에 따로 복사한다.

### 실제 프로세스 중단

`--save-crash`는 앱과 같은 `ProjectStore`를 실행하는 전용 자식 프로세스를 다음 지점에서 대기시키고 부모 프로세스가 강제 종료한다. 예외 주입과 달리 저장 코드의 catch/finally가 실행되지 않는다. 일반 앱 저장에는 콜백을 전달하지 않으며, 검증 지점은 내부 API다.

| 종료 지점 | 신규 저장 | 기존 프로젝트 덮어쓰기 |
|---|---|---|
| 이미지 기록 후, manifest 전 | 미완성 staging은 열기 거부 | 원본 바이트 보존 |
| staging 전체 읽기 검증 후 | 완성 staging 보존 | 원본 바이트 보존 |
| 게시 직전 | 완성 staging 보존 | 기존 파일은 `.comp.recovery`에 보존 |
| 게시 직후, 복구 사본 정리 전 | 새 프로젝트 열기 가능 | 새 프로젝트와 이전 복구 사본 모두 보존 |

새 검증 프로세스에서 문서·레이어·픽셀·선택 상태를 확인하고, 기존 패키지 전체 SHA-256으로 원본 보존을 확인한다. 복구 사본이 있으면 기존 경로 덮어쓰기가 거부되고, 복구 사본을 새 이름으로 저장해 다시 열 수 있으며 원본 복구 폴더는 변경되지 않는다. 종료한 프로세스의 파일 잠금 해제도 확인한다. WPF 자체를 저장 도중 종료한 검사는 아니며, 정전·디스크 오류를 검증한 것도 아니다.

첫 저장의 게시 전 중단에는 이전 저장본이 없다. 완성된 staging의 로딩 가능 여부는 진단 도구로 확인하지만, 앱에서 staging을 자동 검색·복구하는 기능은 제공하지 않는다. `.comp.recovery`만 File → Open recovery copy…로 열 수 있다.

### 반복 편집과 성능의 해석

반복 검사는 1024×1024의 3개 레이어에서 붓·지우개, 변환·합성 모드·순서·추가·삭제, Undo/Redo·no-op·취소를 함께 사용한다. 매 스트로크 4점의 화면을 독립된 새 합성 결과와 **바이트 단위 일치**로 비교한다. 저장 왕복과 PNG 출력은 premultiplied/straight 알파 변환에 따른 채널당 1의 반올림만 허용한다. JPEG는 다시 디코딩하여 크기를 확인하며, 손실 압축의 픽셀 일치를 주장하지 않는다.

통합 실행의 1,200회 검사는 179.5초에 완료됐다. 이력 전용 타일 최대 103.5MiB, 이력 최대 100단계였다. 이력 한도는 100단계 및 현재 문서 외의 고유 타일 256MiB다. 새 문서에서 이력이 비워지는지도 검사한다. 프로세스 메모리·핸들 수는 진단값이며 누수 부재를 증명하는 판정 기준은 아니다. 1,200회 실행은 수 분 수준이므로 종일 사용 검증으로 대체하지 않는다.

2026-10-06 10:22 KST, Windows 11 Home 빌드 26300, 논리 프로세서 12개에서 측정한 4K 결과다. 두 스트로크 중 큰 값을 표시한다.

| 레이어 / 총 소스 | 갱신 p95 | 스트로크 종료 | working set 최대 |
|---|---:|---:|---:|
| 1개 / 16MP | 31.36ms | 9.70ms | 474MiB |
| 3개 / 48MP | 25.00ms | 2.99ms | 924MiB |
| 6개 / 96MP | 24.45ms | 2.89ms | 1,299MiB |

모두 초기 내부 기준 p95 ≤33.3ms, 종료 ≤100ms를 통과했다. CPU 모델과 1000×1000 offscreen Skia 합성만 포함하며 실제 입력 지연·WPF 표시·다중 DPI를 포함하지 않는다. 레이어 수와 무관한 시스템 부하 및 워밍업 영향이 있어 표를 선형 성능 비교로 해석하지 않는다.

복사한 배포본은 공백이 있는 경로 및 다른 작업 디렉터리에서 실행하고, 자식 프로세스의 PATH를 System32로 제한하며 공유 .NET 검색 경로를 존재하지 않는 위치로 지정한다. 실제 로드된 `coreclr.dll`, `libSkiaSharp.dll`, `Compositor.Native.dll`이 복사한 폴더 안에 있는지도 확인한다. **현재 개발 PC에 설치된 OS 구성 요소의 영향을 제거한 VM 검증은 아니다.**

## 실기 검증: 4점 완료, 4점 잔여

아래는 자동 테스트로 완료 표시하지 않는다. 검증자는 앱 커밋/배포본, OS, 장비, 날짜, 실제 결과와 실패 시 재현 순서를 기록한다.

| ID / 가중치 | 필요한 환경 | 절차와 합격 기준 | 상태 |
|---|---|---|---|
| M1 / 3 | 실제 Mac 원본 앱 + Windows 앱 | Mac에서 투명 PNG/JPEG, 빈 레이어, 7개 지원 합성 모드, 표시·불투명도·순서·이동·크기·회전의 대표 문서를 저장. Windows에서 열어 편집 후 별도 이름 저장 → Mac 재열기 → Mac 별도 저장 → Windows 재열기. 이미지·레이어·값·좌표·선택 보존, 읽기 실패/미지원 기능 손실 없음. 원본 별도 보존. | 미검증 |
| M2 / 2 | 물리 마우스 | 붓/지우개/이동/Hand 각각 창 밖으로 드래그하고 복귀. 왼쪽 드래그 중 오른쪽/가운데 버튼, 휠, Esc, Alt+Tab 실행. 혼합 버튼이 편집을 임의 완료하지 않고, Esc/창 비활성화/캡처 상실은 미완료 편집 취소. 이후 새 입력 정상, Undo/Redo·수정 표시 일관성. 각 조합 10회. | 완료 — 사용자 실기 확인 |
| M3 / 2 | 배율이 다른 모니터 2개 | Windows 배율 100/150/200% 조합에서 창 이동·최대화·복원 및 모니터 연결 변경. 커서와 브러시/선택 위치 일치, 표시 잘림·오프셋 없음, 확대/이동 후 입력 정상, PNG 내보내기 동일. 자동 렌더 배율 검사는 이를 대체하지 않음. | 완료 — 사용자 실기 확인, 증거 범위는 아래 참고 |
| M4 / 1 | SDK/Visual Studio 없는 Windows 11 x64 PC | `artifacts/publish` 폴더 전체를 복사해 일반 사용자로 실행. PNG/JPEG 열기, 편집, 저장·재열기·출력, 종료/재시작. 최소 2시간 혼합 편집하며 15분 간격 메모리/핸들 및 저장본 기록. 누적 증가·정지·데이터 손실이 있으면 재현 조사 후 재검증. | 미검증 |

M1은 저장 결과와 지원 범위를 검증한다. Mac 고품질 축소 필터 및 브러시 교차부 농도는 현재 구현과 다르므로 두 플랫폼에서 새로 그린 스트로크가 픽셀 단위로 같다는 합격 기준을 추가하지 않는다. 같은 PNG 픽셀과 Nearest 기준 문서도 포함하여 좌표·알파 오류를 분리한다.

Mac 실기용 시작 자료로 반복 검사 보고서의 `artifacts` 경로 안 `working.comp`, `output.png`, `output.jpg`를 복사할 수 있다. 단, Windows에서 만든 자료만 열어보는 것으로 M1을 완료하지 않으며 Mac에서 직접 만든 문서도 왕복해야 한다. `.comp`는 디렉터리 전체를 옮긴다.

완료 조건은 M1–M4의 결과 기록과 발견 결함의 수정·재검증이다. 그 전까지 다음 작업은 그림자나 PSD 추가가 아니라 해당 실기 검증이다.

## 현재 PC 실기 세션 (2026-10-06)

사용자가 별도 장비는 없으며 현재 PC에서 직접 조작할 수 있다고 확인했다. Windows 11 Home 빌드 26300에서 모니터 3대를 확인했다: 주 모니터 3840×2160 / 150%, 왼쪽 1920×1080 / 100%, 오른쪽 세로 1080×1920 / 100%. 이는 장비 확인이며 입력·DPI 검증 통과를 의미하지 않는다. 실제 Mac 왕복(M1)과 개발 도구 없는 별도 PC(M4)는 현재 환경에서 수행할 수 없다. M2/M3는 사용자가 전체 마우스 항목과 100/150/200% 및 모니터 연결 변경을 확인했고 특별한 문제가 없다고 보고하여 실기 완료로 반영했다.

배포 앱을 띄우고 `watch-manual-validation.ps1`로 실제 창의 DPI, 모니터 식별값, 물리 화면 좌표, 메모리·핸들을 1초마다 관찰할 수 있다. 도구는 키보드·마우스 입력을 주입하거나 디스플레이 설정을 변경하지 않는다. 정해진 시간 또는 대상 앱 종료 시 기록을 끝내며 앱을 종료하지 않는다.

```powershell
# Get-Process Compositor.Windows로 대상 앱 ID를 확인하고 1234를 실제 값으로 바꾼다.
powershell -NoProfile -ExecutionPolicy Bypass -File watch-manual-validation.ps1 -AppProcessId 1234 -Minutes 20 -OutputPath artifacts/manual-session.jsonl
```

`sample` 행의 `dpi` 96/144/192는 각각 100/150/200%다. 모니터와 DPI 변경 기록만으로 커서 정렬, 잘림, 취소 또는 Undo가 정상임을 판정하지 않는다. 모니터 이동 전후 PNG는 동일 문서로 출력해 비교한다. 실제 수행한 배율·연결 변경 범위와 물리 마우스 반복 횟수를 함께 남기고, 수행하지 않은 조합은 미검증으로 유지한다. JSONL은 지정 경로를 새로 쓰므로 이전 기록을 보존하려면 새 파일명을 사용한다.


### 사용자 확인 결과
