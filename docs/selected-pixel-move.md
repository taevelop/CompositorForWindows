# 선택 픽셀 이동 기반

2026-10-06. 내부 연산 기반을 구현했다. 아직 Ctrl-drag/방향키/복사·붙여넣기 UI에 연결하지 않았으며 사용자 기능 완료로 계산하지 않는다.

## 구현

- SelectedPixelTransfer.Lift: 문서 좌표 선택 농도를 소스 픽셀 중심에 적용해 선택 픽셀과 잘라낸 원본을 만든다. 명시적 빈 선택·투명 픽셀만 있는 범위는 null이다.
- CompositeOnto: 처음 추출한 픽셀을 제공된 기준 래스터 위에 premultiplied source-over로 합성한다. 매 미리보기에 같은 CutSource 또는 원본을 사용해야 이동이 누적되지 않는다.
- 정수 오프셋은 정확한 픽셀 복사, 소수 오프셋은 Smooth의 bilinear 또는 High의 Catmull-Rom cubic 샘플링을 사용한다. 샘플은 이웃 타일을 함께 참조하므로 타일 경계가 이미지 경계처럼 취급되지 않는다.
- RasterReframe: 픽셀 좌표 범위를 바꾸면서 원본의 문서 좌표 위치를 유지한다. 원래 범위 밖의 이미지 픽셀은 투명, 마스크는 원본처럼 흰색이다. 1×1 균일 마스크도 원래 소스 크기로 확장해 기존 영역 농도를 유지한다.
- 256px에 맞는 재배치는 기존 타일을 공유한다. 변경 없는 입력은 원본 참조를 유지한다. 회전·양축 뒤집기·레이어 속성은 유지한다.
- 취소 토큰과 이미지 크기 제한을 검사한다.

## 원본 및 한계

macOS/Compositor/Document/BrushStroke.swift의 liftSelection, moveLifted, transform(for:), BrushCommit.expandMask 및 EditorSession+Brush.swift를 대조했다.

원본은 소스 범위와 역변환한 캔버스 범위의 합집합 안에서 이동한 픽셀을 합성하고, 확정 때 알파가 있는 경계로 잘라낸다. 현재 기반은 호출자가 목적 래스터와 프레임을 제공하는 구조다. 캔버스 허용 범위, 최종 알파 경계, 문서 합산 이미지/마스크 예산과 Undo 제한을 연결하는 편집 조정기가 아직 필요하다.

CoreGraphics의 high 보간과 Windows cubic의 실제 결과 동등성은 증명하지 않았다. 정수 이동은 정확하게 검증했고, 소수 이동은 타일 이음새·premultiplied 불변성을 검증했다. 실제 Mac 비교는 보류 상태를 유지한다.

## 검증

396개 코어 테스트 통과. 새 테스트는 선택 추출/잘라내기, 투명 범위, 반투명 합성/복제, 두 샘플러의 타일 경계, 반복 미리보기 불변성, 미변경 타일 공유, 회전 좌표, 취소/잘못된 값, 정렬/비정렬 프레임, 양축 뒤집기, 균일 마스크 확장 및 회전 레이어 밖 이동의 연산 조합을 포함한다.

## 다음 연결

1. 원본 대비 캔버스 허용 범위와 타이트한 최종 알파 경계, 합산 픽셀/Undo 예산.
2. 픽셀+이동한 선택을 같은 트랜잭션으로 관리. 0 오프셋은 완전 무변경, 취소는 원본 복구.
3. Ctrl-drag 이동, Ctrl+Alt-drag 복제, Ctrl+방향키 이동. 마스크·조정 레이어·숨긴 레이어 제한.
4. 선택 복사/잘라내기/붙여넣기 및 외부 Windows 클립보드 알파·포맷.
5. 실제 WPF 입력/취소/이력/저장 재열기와 큰 선택 영역 성능.

최종 ./build.ps1 -Test에서 Release 경고/오류 0, 396개 코어 테스트 및 기존 실제 WPF 회귀 검증이 통과했다. 이번 단계는 UI에 노출하지 않았으므로 배포 패키지의 사용자 기능 추가를 주장하지 않는다.
