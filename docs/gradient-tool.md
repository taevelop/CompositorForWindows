# 그라디언트 구현 현황

2026-10-07: 원본 Document/Gradient.swift, BrushStroke.fillGradient, UI/GradientControls.swift 대조 후 연산 기반을 추가했다.

- 선형: 시작→끝 벡터 투영, 범위 밖 끝점 색 연장.
- 방사형: 시작 중심, 시작~끝 거리 반지름, 반지름 밖 끝점 색 연장.
- 전경→배경 및 전경→투명, 반전과 전체 불투명도.
- 문서 좌표에서 계산하고 기존 채우기의 이미지 격자 확장·선택 농도·마스크 범위/회색 규칙·취소·Undo 비용 계산을 공유한다.
- 원본과 같이 0.5픽셀 미만 선은 무변경이다. 결과는 입력 문서로부터 새 불변 문서를 계산하므로 이후 미리보기는 항상 시작 문서를 입력해야 한다.

코어 559개 통과: 선형 끝점/중간/반전, 반투명 소스 오버 합성, 투명 끝점의 원본 보존, 마스크 불투명 회색, 방사형/범위 밖 색 연장, 짧은 선과 잘못된 설정. 기존 팔레트 채우기 검사를 함께 유지한다. 현재는 CPU의 sRGB 채널 보간 규칙이며 실제 Mac CoreGraphics 결과의 모든 반투명/소수 경계 바이트 동등성을 검증한 것은 아니다.

아직 도구 UI에 연결하지 않았다. 남은 작업은 G 도구·캔버스 선/끝점 핸들·Shift 규칙, 형태 버튼·그라디언트 견본·스타일·반전·불투명도 슬라이더, 원본 기준 반복 미리보기, Apply/Cancel/Enter/Esc와 도구/레이어 전환 확정, 팔레트·탭별 설정, 비동기 대형 미리보기/취소·저장 왕복/화면 출력 검사다. 현재 기반 단계만으로 도구 완료로 계산하지 않는다.

## 편집 트랜잭션 기반

2026-10-07: GradientEdit가 시작 문서/레이어/마스크 대상을 캡처해 세션 트랜잭션을 시작한다. 설정 변경마다 원본에서 비동기 계산하며 직전 요청을 취소한다. SemaphoreSlim으로 연산을 직렬화해 동시 대형 이미지 작업을 막고 최신 요청만 미리보기에 적용한다. CommitAsync는 마지막 미리보기를 기다린 뒤 한 번의 Undo로 확정하며 대기 중 설정 변경을 거부한다. Dispose는 자신이 소유한 미리보기만 취소하고, 외부에서 문서를 교체한 경우 그 문서를 덮어쓰지 않는다.

코어 564개 통과: 반복 설정 변경의 원본 기준 결과, 단일 Undo/Redo, 대기 중 취소, 최신 요청 우선, 짧은 선 원본 복원, 외부 문서 교체 후 결과 폐기, 확정 중 설정 변경 차단. 클래스는 UI 스레드 소유이고 불변 픽셀 계산만 worker에 보낸다. 아직 G 도구/캔버스 입력/설정 패널에는 연결하지 않았으며 실제 UI 전환·저장 확정/취소 검사와 대형 미리보기 측정은 다음 단계다.
편집 기반 최종 검증: 경고/오류 0, 코어 564개 및 기존 WPF 회귀 통과. 사용자 도구 UI가 아직 없어 새 배포 패키지는 생성하지 않았다.
